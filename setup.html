△점과 점교사 연결 안내놀이로 돌아가기
최초 한 번 준비하기

각자의 기기에서 만나는 놀이판

웹앱 화면은 완성되어 있습니다. 서로 다른 두 기기가 놀이판을 공유하려면 교사 소유의 Firebase 프로젝트를 연결해야 합니다. 학생은 계정·이메일·비밀번호를 입력하지 않고 별명과 방 코드로 참여합니다. 앱은 Firebase의 익명 인증으로 기기를 구분합니다.

바로 규칙을 확인하려면 첫 화면의 한 기기에서 규칙 체험하기를 누르세요. 이 모드는 실시간 연결 없이 두 사람이 같은 화면에서 번갈아 조작하는 체험입니다.

01 · 프로젝트

Firebase 프로젝트와 웹앱 만들기

  1. Firebase 콘솔에 교사의 Google 계정으로 접속합니다.
  2. 프로젝트 만들기를 선택합니다. 이름은 예를 들어 triangle-class-game으로 정합니다. Google Analytics는 이 게임에 필요하지 않습니다.
  3. 프로젝트 개요에서 웹앱 아이콘 (</>)을 눌러 웹앱을 등록합니다. Firebase Hosting 설정은 지금 필요하지 않습니다.
  4. 표시되는 const firebaseConfig = { ... }; 부분을 복사합니다. 아래 데이터베이스를 만든 후 주소도 추가합니다.

기존 프로젝트도 사용할 수 있지만, 이 게임 전용 프로젝트라면 보안 규칙을 구분하기 쉽습니다.

02 · 익명 인증

익명 로그인을 활성화하기

  1. 콘솔의 Authentication을 열고 시작합니다.
  2. 로그인 방법 / Sign-in method에서 익명 / Anonymous 제공업체를 사용 설정하고 저장합니다.

학생이 로그인 화면을 사용하는 것은 아닙니다. 앱이 자동으로 임시 사용자 ID를 받아 방의 두 참여자를 구분합니다.

03 · 데이터베이스

Realtime Database 만들기

  1. Realtime Database → 데이터베이스 만들기를 선택합니다. Cloud Firestore가 아닙니다.
  2. 제시된 위치 중 교실과 가까운 위치를 선택하고, 잠금 모드로 시작합니다.
  3. 데이터 화면 위의 데이터베이스 주소를 복사합니다. 예: https://프로젝트명-default-rtdb.asia-southeast1.firebasedatabase.app
  4. 아래 예시처럼 웹앱 설정에 databaseURL로 넣습니다.
{
  "apiKey": "Firebase 웹앱의 apiKey",
  "authDomain": "프로젝트명.firebaseapp.com",
  "databaseURL": "복사한 Realtime Database 주소",
  "projectId": "프로젝트 ID",
  "appId": "Firebase 웹앱의 appId"
}

콘솔이 준 설정에 storageBucket, messagingSenderId가 포함되어 있어도 그대로 붙여 넣을 수 있습니다.

04 · 보안 규칙

게임용 보안 규칙 게시하기

  1. database.rules.json 내려받기를 눌러 파일을 받습니다.
  2. 파일을 메모장으로 열어 내용 전체를 복사합니다.
  3. Firebase의 Realtime Database → 규칙 / Rules에 붙여 넣고 게시 / Publish합니다.
이 규칙은 루트 전체 조회를 막고, 대결 중인 방은 그 방의 두 참여자에게만 읽기·쓰기를 허용합니다. 빈 방은 코드로 입장할 수 있습니다. 차례와 기록 추가를 검사하며, 이전 선분 기록은 수정할 수 없습니다. 읽기·쓰기를 모두 true로 여는 규칙은 사용하지 마세요.
기하학 판정과 점수는 두 기기에서 동일한 코드로 계산합니다. 악의적인 클라이언트의 기하학 조작까지 서버가 검증하는 대회용 구조는 아닙니다.

05 · 앱 연결

연결 정보를 넣고 학생 링크 만들기

  1. 놀이 첫 화면에서 교사 설정을 누릅니다.
  2. 웹앱 설정 객체 또는 const firebaseConfig = { ... };를 그대로 붙여 넣습니다. 반드시 databaseURL을 포함하세요.
  3. 저장하고 연결 확인을 눌러 익명 인증과 방 생성·삭제가 되는지 확인합니다.
  4. 연결 성공 후 학생 접속 링크를 복사하여 학급 게시판·Teams·QR 생성 도구 등으로 공유합니다. 이 링크를 통해 모든 학생 기기가 같은 DB에 연결됩니다.

설정은 교사가 사용한 브라우저에 기억됩니다. 학생 접속 링크에는 Firebase의 공개 웹앱 연결 정보가 포함되며, 관리자 권한의 비밀키는 포함하지 않습니다. 서비스 계정 JSON이나 개인키를 입력하지 마세요.

현재 주소가 ChatGPT 로그인을 요구한다면 학생에게 사용하지 마세요. 아래의 GitHub Pages 배포 방법으로 계정 입력 없는 주소를 만들 수 있습니다.

06 · 두 기기로 확인

수업 전 연결 확인하기

  1. 서로 다른 두 기기에서 학생 접속 링크를 엽니다. 한 기기만 있다면 일반 창과 시크릿 창을 사용합니다. 같은 브라우저의 탭 두 개는 같은 참여자로 구분됩니다.
  2. 첫 기기에서 별명을 입력하고 대결 방 만들기를 누릅니다.
  3. 두 번째 기기에서 다른 별명과 첫 기기의 8자리 방 코드를 입력해 입장합니다.
  4. 각자 가위바위보를 고릅니다. 양쪽 선택이 끝나야 결과가 공개되며, 비기면 다시 선택합니다.
  5. 선공이 점 두 개를 선택하고 선분 그리기를 누릅니다. 상대 화면에 같은 선분이 나타나는지, 차례가 바뀌는지 확인합니다.
  6. 삼각형이 완성되면 소유자와 점수가 양쪽에 같은지 확인합니다.

수업에서는 짝마다 방을 하나씩 만들면 됩니다. 교사가 DB를 따로 나눌 필요는 없습니다. 방에는 최대 두 사람만 입장할 수 있습니다.

수업 운영

놀이판과 종료 방식

  • 기본은 점 20개이며, 방을 만들 때 12개·20개·30개 중에서 선택합니다. 좌표가 조금씩 달라 다양한 삼각형을 만들 수 있습니다.
  • 선분의 교차와 다른 점의 통과를 금지합니다. 직접 연결된 세 변으로 완성한 삼각형을 셉니다.
  • 마지막 변을 그린 사람에게 예각 1점·직각 2점·둔각 3점이 돌아갑니다. 한 선분으로 두 삼각형을 완성하면 둘 다 얻습니다.
  • 삼각형을 완성해도 차례는 상대에게 넘어갑니다. 가능한 선분이 없으면 자동으로 종료하며, 동점은 무승부입니다.
  • 완성한 삼각형 목록을 누르면 각도와 분류 이유를 살펴볼 수 있습니다. 판정은 실제 좌표를 사용하며 표시 각도만 소수점 한 자리로 반올림합니다.
  • 새로고침하면 같은 브라우저의 익명 사용자 ID로 기존 방에 다시 입장할 수 있습니다. 친구의 연결이 끊기면 연결 상태가 표시됩니다.
  • 방은 6시간 후 접근이 만료됩니다. 자동 삭제되지는 않으므로 수업 후 Firebase 데이터 화면에서 rooms와 presence를 삭제할 수 있습니다. 방을 만든 사람이 나가기를 누르면 그 방은 닫힙니다.

선택 · 직접 배포하기

GitHub Pages에 올리기

  1. 웹앱 전체 파일을 내려받아 압축을 풉니다.
  2. 교사 설정 링크로 연결 정보를 공유할 수도 있고, config.js의 window.TRIANGLE_FIREBASE_CONFIG = null;에서 null을 자신의 Firebase 설정 객체로 바꿀 수도 있습니다. 파일에 넣으면 학생 URL에 설정을 붙일 필요가 없습니다.
  3. GitHub 저장소에 압축을 푼 내용물을 올립니다. index.html이 저장소 맨 위에 있어야 합니다.
  4. Settings → Pages → Deploy from a branch에서 main과 /(root)를 선택해 저장합니다.
  5. 생성된 https://사용자명.github.io/저장소명/ 주소를 학생들에게 공유합니다. Firebase DB는 계속 같은 프로젝트를 사용합니다.

이 웹앱은 정적 HTML·CSS·JavaScript로 구성되어 별도의 서버 설치 없이 HTTPS로 배포할 수 있습니다. 파일을 더블클릭해서 여는 방식은 모듈 실행이 제한될 수 있으므로 배포한 주소로 접속하세요.

연결이 안 될 때

  • operation-not-allowed: Authentication에서 익명 로그인을 켭니다.
  • permission_denied: Realtime Database에 제공한 보안 규칙을 게시했는지, 6시간이 지나지 않았는지 확인합니다.
  • databaseURL 없음: Realtime Database 주소를 firebaseConfig에 추가합니다.
  • 같은 사람이 두 번 접속됨: 다른 기기 또는 다른 브라우저·시크릿 창을 사용합니다.
  • too-many-requests: 같은 학교 IP에서 익명 사용자 생성이 한꺼번에 몰릴 수 있습니다. 순차 입장으로 다시 확인하고, 지속되면 Firebase 콘솔에서 익명 인증 할당량을 확인합니다.
  • 선분이 동기화되지 않음: 두 기기가 같은 DB와 같은 방 코드를 사용하는지, Firebase와 www.gstatic.com 접속이 학교망에서 허용되는지 확인합니다.
  • 가위바위보 도중 브라우저를 바꿈: 비공개 선택 기록은 원래 탭에 보관합니다. 같은 탭에서 재접속하거나 새 방을 만듭니다.
